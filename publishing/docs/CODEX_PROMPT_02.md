# 작업 2 — 서버 연결 후 초안 복구와 실사용 보완

**작업 1의 완료 결과를 확인한 뒤에만 사용. 지금 동시에 실행하지 않는다.** 새 기능 세션으로 시작하되 먼저 작업 1 변경이 저장·정리됐는지 확인한다.

목표: 이미 동작하는 Django 스마트메모의 네트워크 실패·초안 복구·모바일 입력 흐름을 보완한다. 새 편집기나 디자인을 만들지 않는다.

1. 적용 지침과 `docs/implementation-status.md`를 먼저 읽고 관련 저장 코드만 확인한다. 이전 연구·전체 프로젝트·번들을 다시 읽지 않는다.
2. 로그인 owner별·문서별 IndexedDB 초안을 저장한다. 서버 성공과 로컬 보관 상태를 구분하고, 서버 revision·로컬 수정 시각과 비교해 복구 선택을 제공한다. 조용히 최신 서버 내용을 덮지 않는다.
3. 저장 중 추가 입력, 실패 후 재시도, 다른 기기 409에서 현재 초안 보존·JSON 보관을 확인한다. 로그아웃 시 공유 기기에서 다른 사용자에게 초안이 노출되지 않는 정책을 적용한다.
4. 한글 composition을 방해하지 않도록 저장·메뉴·DOM 갱신을 확인한다. 모바일 키보드·safe-area·서식 메뉴가 본문을 가리지 않게 조정한다.
5. 자동화 가능한 저장 실패·응답 순서·owner 분리·복구 충돌 테스트만 추가한다. Android IME는 실제 기기 확인 없이 통과했다고 쓰지 않는다.
6. 변경 후 필요한 검사만 실행하고 상태 문서를 갱신한다. 배포·AI·협업·추가 기능으로 확장하지 않는다.

서브에이전트, REA, 디자인 재해석, 이유 없는 npm 업데이트·대형 테스트 도구 설치는 하지 않는다. 오류는 원인에 근거해 해결하고 결과를 15줄 이내로 보고한다.
