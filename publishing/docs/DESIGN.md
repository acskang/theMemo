# 스마트메모 — 편집기 화면 설계 v1.0

작성일: 2026-11-10 (한국시간)

프로젝트: theMemo / 서비스: 스마트메모 / 운영 주소: memo.thesysm.com

이 문서는 화면과 상호작용 설계다. 동작하는 앱이나 구현 완료 보고서가 아니다. 시안의 저장 상태, 문서 수, 글자 수는 예시다. 서비스 화면의 기준 언어는 한국어다.

## 1. 목표와 범위

떠오른 생각을 바로 쓰고, 나중에 나만의 블로그에서 찾고 읽는 개인 기록 서비스. 기본 접근은 로그인 사용자 본인으로 제한한다. 블로그 보기 역시 공개 게시판을 의미하지 않는다.

디자인 방향은 다크 네이비의 익숙한 편집 도구 + 조용한 글쓰기 공간 + 메모장/태그/날짜 기반 탐색이다. 읽기와 작성에서 본문 서체, 폭, 이미지와 인용문 표현을 공유한다.

## 2. 입력 자료의 신뢰 범위

### 네이버 스마트에디터

사용자 스크린샷과 REA 접근성 관찰에서 제목·본문, 사진·인용구·링크·파일·표, 글자 크기·밑줄·글자색·배경색·정렬·목록 등의 UI를 확인했다. 스크린샷에는 글꼴·굵게·기울임 도구도 보였다.

네이버 내부 문서 모델, 저장 형식, 서식 처리 코드는 확인하지 못했다. 수집된 JavaScript에는 Frameset 자산이 포함됐으나 분석이 시간 제한으로 끝났다. 본 문서의 문서 모델과 저장 정책은 스마트메모를 위한 독립 설계이며 네이버 구현을 복원한 것이 아니다. 네이버 추가 분석은 종료한다.

### 회사 디자인

첨부된 theAccounting, theDetect, DrawingBQ, THESYSM 포털, theUI 화면을 색상·위계 참고로 사용했다. 네이비/차콜 표면, 얇은 슬레이트 경계, 밝은 본문, 하늘색 강조를 이어간다. 아래 HEX는 시각적으로 재구성한 새 설계 토큰이며 기존 제품에서 추출한 공식 토큰으로 단정하지 않는다.

## 3. 공식 자료 조사와 적용 판단

|---|---|---|
| Notion Writing & Editing | 문단 옆 +, 블록 핸들, / 명령, 선택·블록 단위 작업 | 마우스용 + 삽입과 키보드용 / 메뉴를 함께 제공. 드래그만으로 이동하게 만들지 않음 |
| Craft Write | 텍스트·체크리스트·사진을 블록으로 정리, 여러 기기에서 기록 | 메모를 텍스트와 사진의 자연스러운 흐름으로 표현. 기기 간 동기화는 앱에서 별도 구현 |
| Obsidian Daily Notes | 오늘 날짜의 노트 열기/생성, 일기 템플릿 | 오늘의 기록 버튼과 단순한 일기 시작 템플릿 |
| WordPress Block Editor | 상단 도구, 콘텐츠 영역, 접을 수 있는 설정·목차 | 왼쪽 탐색 + 중앙 본문, 우측 목차는 선택적으로 열기 |

| Tiptap | headless, ProseMirror 기반, 확장형, plain JS·Alpine 통합, JSON/HTML | 프로젝트 기술과 브랜드 UI에 맞는 우선 구현안 |

이 비교는 공식 설명과 문서 검토를 근거로 한 설계 판단이며, 모든 서비스의 로그인 화면을 직접 조작하거나 성능 비교한 결과는 아니다.

브랜드 마크와 주요 버튼만 선명한 하늘색을 사용한다. 긴 글을 읽는 영역에는 과도한 광택·글로우·강한 그라데이션을 쓰지 않는다. 오류·저장 상태는 색뿐 아니라 아이콘과 텍스트로 표현한다.

서체 제안: 로컬 배포하는 Pretendard 또는 Noto Sans KR, 없으면 시스템 sans-serif. 기본 본문 17px, 행간 1.85, 모바일 17px/1.8. 제목은 데스크톱 32px, 모바일 28px. UI는 14px 이상을 기본으로 한다. 본문 글꼴과 크기는 문서 서식 도구로 조정할 수 있다.

간격은 4/8/12/16/24/32/48px 체계. 패널 radius 12px, 버튼 8px, 입력 최소 높이 40px, 모바일 주요 터치 영역 44×44px 이상을 설계 목표로 한다. 본문 폭은 대략 700~760px이며 사용자 확대·긴 문자열·320px 화면에서도 읽기 흐름을 유지한다.

## 5. 데스크톱 작성 화면

### 앱 상단

- 브랜드: theMemo | 스마트메모.
- 보기 전환: 작성 / 블로그 보기. 미저장 변경이 있다면 이동 전에 저장 결과를 확인한다.
- 전체 메모 검색: 제목·본문·태그를 대상으로 검색, Ctrl/Cmd+K로 열기.
- 계정 메뉴: 본인 계정, 표시 설정, 로그아웃.

### 왼쪽 탐색

폭 220~240px. 새 메모, 오늘의 기록, 모든 메모, 즐겨찾기, 메모장 목록, 태그, 휴지통, 설정. 메모장과 태그 목록은 길어지면 자체 스크롤한다. 휴지통·설정을 하단에 고정하더라도 좁거나 낮은 화면에서 본문과 겹치지 않게 한다.

오늘의 기록은 날짜 기반 일기 한 건을 열거나 생성한다. 새 메모는 같은 날짜에도 여러 건 만들 수 있다. 일기의 기록 날짜는 작성 시각과 별도로 변경할 수 있도록 한다.

### 문서 상단

경로 / 저장 상태 / 집중 모드 / 읽기 / 저장 순서. 저장 버튼은 Ctrl/Cmd+S와 같은 즉시 서버 저장 동작이다. 자동 저장과 수동 저장은 동일한 저장 경로를 사용한다. 기본 비공개 서비스이므로 발행 버튼은 두지 않는다.

### 편집 도구 모음

상단 고정 1행: 실행 취소·다시 실행 / 본문·제목 단계 / 글꼴·크기 / 굵게·기울임·밑줄 / 글자색·강조색 / 정렬·목록 / 링크 / + 삽입. 좁아지면 보조 기능을 더 보기로 이동한다. 도구마다 이름·단축키 툴팁과 선택 상태를 제공한다.

삽입 메뉴의 기본 순서: 사진, 체크리스트, 글머리 목록, 번호 목록, 인용문, 구분선, 코드 블록, 표, 파일. 표·파일은 후속 단계 기능이지만 메뉴 위치를 예약한다. 아직 구현하지 않은 기능은 정상 동작하는 것처럼 표시하지 않는다.

### 작성 영역

선택적인 표지·아이콘 → 기록 날짜 → 제목 → 메모장·태그 → 본문. 제목 없이도 빠르게 입력 가능하며 저장 시 목록에는 ‘제목 없는 메모’를 표시한다. 별도의 필수 분류 입력으로 기록을 막지 않는다.

본문은 일반 문단·제목·목록·체크리스트·인용문·사진이 자연스럽게 이어진다. 문단에 포인터를 올리거나 키보드로 접근할 때 +와 이동 핸들이 나타난다. 블록 메뉴에는 위로/아래로 이동을 제공해 드래그를 대체한다.

텍스트 선택 시 작은 메뉴(굵게·기울임·링크·강조)를 표시한다. 이 메뉴는 선택 내용과 다른 도구를 가리지 않게 배치하고 Esc로 닫는다. 항상 표시되는 상단 도구도 있으므로 선택 메뉴를 발견하지 못해도 사용할 수 있다.

빈 문단에서 /를 입력하면 ‘제목, 사진, 할 일, 인용, 코드’ 메뉴가 열린다. 한글 별칭 검색을 지원하며 한글 조합 중에는 명령을 실행하지 않는다. / 메뉴만으로 기능을 찾도록 강요하지 않는다.

사진은 파일 선택, 드래그, 클립보드 붙여넣기로 추가한다. 업로드 상태, 실패 시 재시도, 캡션, 대체 텍스트, 크기·정렬 조절을 제공한다. 업로드 중인 사진을 서버 저장 완료로 표시하지 않는다.

### 오른쪽 패널과 집중 모드

오른쪽 220~240px 패널: 목차 / 문서 정보. 목차는 제목 단계로 생성하고 실제 존재하는 제목만 표시한다. 문서 정보는 메모장, 기록 날짜, 생성·수정 시각, 태그, 비공개 상태. 기본값은 닫힘, 데스크톱 시안은 기능 설명을 위해 열린 예시다. 열린 상태가 본문 최소 폭을 침해하면 drawer로 바꾼다.

집중 모드는 왼쪽 탐색과 오른쪽 패널을 숨기고 본문 폭을 유지한다. 저장 상태, 저장 버튼, 집중 모드 종료는 남긴다. Esc는 먼저 열린 메뉴를 닫고, 메뉴가 없을 때 집중 모드를 종료한다.

### 상태 표시

문서 하단에 글자 수·예상 읽기 시간과 비공개 상태를 둔다. 저장 상태는 문서 상단을 기준으로 하며 중복 성공 토스트를 매번 띄우지 않는다. ‘저장됨’은 서버 확인 응답을 받았을 때만 표시한다.

## 6. 블로그형 조회

편집 화면과 동일한 색상·본문 스타일을 사용한다. 상단에서 검색·메모장·태그·날짜를 조합하고 최신 기록을 날짜별 세로 피드로 보여준다. 각 기록은 날짜, 제목, 발췌, 태그, 사진이 있을 경우 작은 썸네일을 제공한다. 사진이 없는 기록에 빈 이미지 칸을 만들지 않는다.

기본은 읽기 편한 세로 피드, 선택으로 간단 목록을 제공한다. masonry 그리드는 날짜 순서 파악을 어렵게 하므로 기본으로 쓰지 않는다. 날짜 그룹은 오늘/어제/월별로 구분한다.

기록 상세에서는 편집 도구를 숨기고 본문, 날짜·태그, ‘수정’, 이전·다음 기록을 제공한다. 목록 필터와 스크롤 위치를 기억해 돌아왔을 때 읽던 곳을 찾기 쉽게 한다. 공개 URL과 공유 기능은 초기 범위에서 제외한다.

## 7. 모바일

- 1024px 미만: 왼쪽 탐색을 drawer로 전환, 오른쪽 패널은 sheet로 전환. 실제 전환은 열 개수가 아니라 확보 가능한 본문 폭으로 판단한다.
- 640px 미만: 좌우 여백 20~24px, 제목 28px, 본문 17px. 부가 메타데이터는 줄바꿈·접기.
- 상단: 뒤로, 메모장, 저장 상태, 저장. 긴 breadcrumb와 전체 검색 필드는 접는다.
- 작성 중: 기본 도구를 단순화하고 서식·삽입 메뉴는 하단 sheet로 연다. 키보드 표시 시 visual viewport와 safe-area를 고려해 도구가 키보드에 가려지지 않게 한다.
- 소프트 키보드가 열리면 앱 하단 탐색은 숨기고 작성 동작을 우선한다. 닫히면 메모/블로그/검색 탐색을 복원한다.
- 키보드가 닫힌 시안의 하단 도구는 화면 레이아웃 예시다. 실제 기기 키보드 대응은 구현 검증이 필요하다.
- 사진은 길게 누르기만 강요하지 않고 명시적인 메뉴 버튼을 제공한다.

## 8. 저장·복구·충돌 상태 설계

| 상태 | 사용자 문구 | 동작 |
|---|---|---|
| 편집 직후 | 저장 대기 | 브라우저 초안과 debounce 예약 |
| 요청 중 | 저장 중… | 최신 변경을 별도로 추적 |
| 서버 확인 | 저장됨 · 시각 | 확인된 revision까지만 성공 표시 |
| 연결 끊김 | 이 기기에 임시 보관 · 서버 미저장 | 로컬 초안 복구, 재연결 후 재시도 |
| 저장 실패 | 저장하지 못했어요 · 다시 시도 | 내용 유지, 즉시 재시도 가능 |
| 다른 기기 변경 | 다른 곳에서 수정된 내용이 있어요 | 현재 초안 보존, 비교 또는 사본 저장 |
| 업로드 중 | 사진 업로드 중… | 파일 완료와 본문 저장을 구분 |

기본 자동 저장 제안은 입력이 멈춘 뒤 약 1.5초, 구현 시 체감과 네트워크를 보고 조정한다. 한글 composition 중에는 편집 DOM을 교체하거나 조합을 방해하지 않는다. Ctrl/Cmd+S는 브라우저 저장 대화상자를 대신해 앱 저장을 실행한다.

브라우저의 초안 보관은 전체 오프라인 서비스나 기기 간 자동 병합을 의미하지 않는다. 서버 revision 비교와 요청 순서 제어로 오래된 응답이 최신 내용을 덮지 않게 한다. 복구 초안은 사용자별로 분리하며 공유 기기 로그아웃 처리도 설계한다.

## 9. 기술 우선안

| 계층 | 제안 | 이유 |
|---|---|---|
| 화면 | Django Template + Tailwind CSS v4 로컬 빌드 | 기존 개발 방식·브랜드 일관성 |
| 화면 상호작용 | Alpine.js | 메뉴·패널·상태 표시 |
| 목록·검색 | HTMX | 필요한 목록 영역만 갱신 |
| 본문 편집 | Tiptap 공개 core + ProseMirror | 직접 UI 설계, vanilla JS·Alpine 공식 통합 문서 |
| 프런트엔드 빌드 | Vite 등 로컬 번들 | 편집기·스타일을 고정 의존성으로 관리 |
| 원본 | 버전이 명시된 Tiptap JSON | 편집 복원·블록 확장 |
| 읽기 표현 | 허용 스키마에서 생성·정제한 HTML | 블로그 조회, JSON과 동일 서식 계약 |
| 검색 | 별도 plain text 추출 | HTML/JSON 문자열 자체를 검색 결과로 노출하지 않음 |
| 이미지 | Django 업로드·권한 확인 다운로드 | 개인 일기의 이미지도 인증 대상 |

Tiptap 공개 코어는 MIT이며 Pro/Cloud 기능과 구분된다. 이 설계는 유료 AI·협업·상용 버전 이력 기능을 기본 전제로 하지 않는다. 필수 확장의 제공 범위와 라이선스는 실제 패키지 선정 시 확인한다. 자동 저장·사용자 인증·업로드·기기 간 충돌 처리는 Django 앱에서 별도 구현해야 한다.

Tiptap 인스턴스를 Alpine 반응형 proxy에 그대로 넣지 않는다. 공식 통합 예제처럼 외부 변수로 관리하거나 raw 처리를 사용한다. HTMX가 활성 편집기 DOM을 바꾸지 않게 하고, 화면 종료 시 편집기·이벤트를 정리한다.

정식 편집기를 단순 contenteditable + execCommand로 직접 만드는 방식은 초기 구현안으로 사용하지 않는다. 프레임워크가 제공하는 문서·선택·undo 처리를 활용하고, UI와 제품 동작에 개발 시간을 사용한다.

## 10. 구현 순서와 검증

1. 디자인 퍼블리싱: 작성·블로그 목록·상세, 모바일, 집중 모드, 메뉴·상태 명세. 샘플 화면과 실제 저장 동작을 구분.
2. 기반 기능: Django 생성, 본인 로그인, 메모/메모장/태그, Tiptap 기본 서식, 저장 후 재편집, 비공개 조회.
3. 일상 사용: 사진, 체크리스트, 자동 저장·초안 복구·revision 충돌, 검색·날짜 필터, 오늘의 기록.
4. 확장: 표·파일·코드 블록 개선, 템플릿, 내보내기, 백업·복원. AI와 실시간 협업은 사용 필요가 생길 때 별도 검토.

첫 본문 통합에서 한글 받침·연속 입력, Enter/Shift+Enter, 선택 후 서식, undo/redo, 여러 줄 붙여넣기, 저장·재열기, Android 키보드를 우선 검증한다. 이후 이미지 업로드 실패·저장 응답 역전·다른 기기 revision 충돌을 검증한다.

기능/작업 단위로 완료 목표를 묶고 성공한 조사·검증을 반복하지 않는다. 네이버 REA 재분석을 다음 세션의 선행 조건으로 넣지 않는다. 화면 재해석을 요구하는 대신 확정된 소스와 이 문서를 Codex CLI에 전달한다.

## 11. 시안 해석

데스크톱 시안은 우측 목차가 열린 예시다. 기본 설정은 닫힘이다. 시안의 버튼·글자 수·저장 시각·가상 기록은 표현용 샘플이며 기능이 구현됐다는 의미가 아니다. 이미지에는 생성 과정에서 간격·라벨·목차의 예시 불일치가 생길 수 있으므로 실제 퍼블리싱은 본 문서와 일치시키고 QA한다. 첨부 이미지의 브랜드 톤을 따르되 핵심 기준은 읽기 편한 본문과 명확한 저장 상태다.
